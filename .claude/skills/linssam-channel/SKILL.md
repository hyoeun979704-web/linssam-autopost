# 린쌤 채널 운영

이 컴퓨터에는 촬영 영상을 자동으로 편집하고 유튜브에 올리는 프로그램(`autopost`)이 설치돼 있다. 이 스킬은 그 프로그램을 점검하고, 사람이 손대야 할 일만 처리한다.

## 채널의 목적 (2026-10-04 확정)

1. **출강 늘리기 (1순위).** 선생님은 문화센터·주민자치센터·평생학습관으로 출강한다. 이 채널은 센터 담당자가 강사를 고를 때 보는 포트폴리오다. 실제 수업 영상, 발표회, 입문 커리큘럼(12스텝)이 핵심 증거다.
2. **천안·아산 수강생 모집.** 조회수·구독자보다 **문의 수**가 기준이다.

담당자용 체크: 채널 맨 위 강사 소개 영상, 센터별 재생목록, 설명란 "출강 문의" 줄, 수업영상의 수강생 동의.
공고: 작업 폴더의 `강사모집공고.md` 를 매주 함께 보고, 마감일·제출서류(이력서·강사신청서·강의계획서)를 정리해 드린다. 천안시 평생학습 "강사은행제" 등록 여부도 확인한다.
강사 소개서: `profile/profile.yaml` 수정 → `scripts/make_profile.py` 실행 → `profile/린쌤_강사소개.pdf`. 출강 이력이 늘면 바로 갱신하고, `[현장 확인]` 이 남은 채로 센터에 보내지 않는다.
홍보: 업로드마다 `홍보문구/` 에 당근·블로그용 글이 생긴다. 당근 모임과 네이버 블로그(thdthdud1234)에 붙여 넣도록 안내한다.

- 문의 경로: 카카오톡 채널 '천안 셔플댄스 · 비너스셔플'(pf.kakao.com/_FRwrX), 당근 모임, 네이버 블로그(blog.naver.com/thdthdud1234).
- 설명란 첫 두 줄(더보기 전에 보이는 곳) = 영상 내용 + 카톡 문의. 바꾸지 않는다.
- 제목·해시태그에 "천안"과 "아산"을 같이 넣는다.
- 월간 점검 때 묻는 것: 이번 달 카톡 문의 몇 건, 그중 "유튜브 보고 왔다"는 몇 건. 선생님께 새 문의가 오면 "어디서 보셨어요?"를 꼭 물어 달라고 한다.
- 네이버 쪽(플레이스·블로그·당근)이 지역 문의를 더 많이 만든다. 유튜브 영상은 블로그 글에 넣어 함께 쓴다.

## 먼저 알 것

- 프로그램 위치: 이 저장소 루트. 실행은 `.venv/bin/python -m autopost <명령>` (윈도우는 `.venv\Scripts\python -m autopost <명령>`).
- 설정: `config.yaml`. 채널명·폴더·수업 안내·시간표가 여기 있다.
- 기록: `~/.linssam-autopost/log.txt`, 대기열 `~/.linssam-autopost/queue.json`.
- 작업 폴더(구글 드라이브): `쇼츠_입문`, `롱폼_라인댄스`(넣는 곳), `완료`(원본 보관), `확인필요`(사람이 볼 것), `.작업중`(편집본).
- 업로드는 Aside 브라우저(선생님 계정)로 유튜브 스튜디오에 올린다.

## 절대 하지 않는 것

- 로그인·로그아웃·계정 전환·비밀번호 입력. 로그인이 풀렸으면 멈추고 선생님께 직접 로그인해 달라고 말한다.
- 스튜디오에 보이는 채널명이 `config.yaml` 의 `channel_name` 과 다르면 업로드하지 않는다.
- 수강생 얼굴이 크게 나온 영상을 동의 확인 없이 올리기.
- 영상 삭제. 비공개 전환까지만 하고, 삭제는 선생님이 직접 한다.
- 없는 숫자나 효과 지어내기("조회수 오를 거예요" 같은 약속).

## 상황별 처리

| 질문 | 할 일 |
|---|---|
| 상태가 `check` 인 영상 | 자동 재시도하지 않는 상태. 파일이 이미 스튜디오에 올라갔을 수 있다. Aside 로 스튜디오 "콘텐츠"의 임시저장·비공개 영상을 확인하고, 이미 있으면 그걸 공개로 바꾸거나 선생님께 묻는다. 없을 때만 status 를 `waiting` 으로 되돌린다 |
| "업로드 됐어?" | `python -m autopost status` 로 대기열을 보여 주고, 실패가 있으면 log.txt 마지막 오류를 쉬운 말로 설명 |
| 실패 다시 올리기 | 원인이 로그인이면 멈추고 안내. 아니면 queue.json 에서 그 항목 status 를 `waiting` 으로, slot 을 지금 시각으로 바꾸고 `tick` 실행 |
| "확인필요에 뭐 있어" | 폴더의 `*_문제.txt` 를 읽고 영상별로 무엇이 문제인지(가로 촬영, 발 잘림, 사람 못 찾음, 너무 김) 말한다. 고쳐 찍을지, 그대로 올릴지 묻는다 |
| 그대로 올리기 | 원본을 원래 폴더로 되돌리고 `config.yaml` 은 건드리지 않는다. 문제 판정이 반복되면 해당 기준(edit 옵션)을 바꿀지 선생님께 확인 |
| 제목·설명 바꾸기 | 올라가기 전이면 queue.json 의 title/description 수정. 이미 올라갔으면 Aside 로 스튜디오에서 수정 |
| 시간표 바꾸기 | `config.yaml` 의 schedule 수정 후 `status` 로 다음 슬롯 확인 |
| "이번 달 채널 어때" | `yt-audit` 순서로 점검. 비교는 이 채널의 지난달과만 한다(다른 채널 평균과 비교하지 않는다) |
| 대본·제목 아이디어 | `yt-script`, `yt-package`, `yt-shorts` 스킬 사용. 말투는 선생님 말투("~해요", 🩵☘️) |

## 영상 양식 (바꾸지 않는 것)

- 쇼츠: 선생님 혼자, 세로, 발끝까지. 위에 "셔플 입문 3/12 - T스텝" 띠, 오른쪽 위 박자 카운트, 마지막 2초 수업 안내.
- 롱폼: 신작은 시연(정면)과 설명(뒤돌아서) 두 편. 썸네일에 곡명 + 난이도.
- 제목: 배우는 동작·곡명 + 난이도 + 지역. 해시태그만 있는 제목 금지.
- 업로드: 정해진 요일·시간에만. 몰아서 올리지 않는다.

## 파일 이름 규칙 (선생님께 안내할 때)

- 쇼츠: `03 T스텝` → 3번째 동작, 이름 T스텝.
- 롱폼: `Lucky Lips` → 곡명. 같은 이름의 `.txt` 를 두면 `레벨:`, `한글:`, `안무:`, `카운트:`, `월:`, `스텝시트:` 줄을 읽어 설명란에 넣는다.
